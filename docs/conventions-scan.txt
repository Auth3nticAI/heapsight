12. OBSERVATIONS & ANOMALIES
========================================================

1. INCONSISTENT PREFIX: Space Shooter lesson IDs don't have a path prefix ("01-boot")
   while all other paths do ("rpg-01-boot", "platformer-01-boot", "robot-01-boot").
   This was a legacy design decision — Space Shooter was the first path built.

2. ORPHANED FILES: src/data/game-templates/simple-rpg/lesson-01-rpg.ts through
   lesson-50-rpg.ts exist on disk but are no longer imported by index.ts.
   Their variant keys ("rpg-01-boot-system") don't match current lesson IDs.

3. MIXED CAPITALIZATION IN SYMBOL NAMES: RPG abbreviation is all-caps in TypeScript
   symbol names (lessonRPG01, ALL_RPG_LESSONS, getRPGLessonById) but lowercase
   in file names (lesson-rpg-01.ts) and folder names (simple-rpg/).

4. GAME TEMPLATE FOLDER vs DB COLUMN DISCREPANCY:
   Folder name:   simple-rpg/     (kebab-case)
   DB column:     simple_rpg      (snake_case)
   TypeScript ID: "simple_rpg"    (snake_case)

5. ROBOT: Folder is "differential-drive-robot/", DB value is
   "differential_drive_robot", but lesson files use the shorter "robot" prefix
   (lesson-robot-01.ts). Robot variant files in game-templates use "-robot.ts" suffix.

6. C++ STYLE: All embedded C++ code uses snake_case for variables/arrays
   (enemy_x, enemy_alive, ship_hp) and camelCase for function names
   (spawnWave, checkDamage). This matches a common C++ game dev style, not strict
   Google C++ Style Guide (which uses PascalCase for functions).
